# V2：按实测边界饱和与置零

新模块为 `exp_fp32_v2`，位于 [rtl/exp_fp32_v2.v](../rtl/exp_fp32_v2.v)。它是独立、可单独编译的 Verilog 文件，不依赖原模块实例。`exp_fp32.v` 保持不变，便于对照和回归。

## 输出规则

使用[边界报告](../analysis/range_boundary/README.md)测得的准确 FP32 端点：

| 条件 | 输出 |
|---|---|
| `x > 88.72283172607421875`，上界位编码 `42b17217` | `7f800000`，正无穷 |
| `x < -87.3365478515625`，下界位编码 `c2aeac50` | `00000000`，正零 |
| 两个边界本身及它们之间的有限输入 | 原计算结果，逐位保持一致 |
| +Inf / -Inf | 分别为 +Inf / +0 |
| 任意正负 NaN，包括 signaling NaN | `7fc00000`，规范 quiet NaN；不保留 payload、不产生异常标志 |

这里使用严格的 `>` / `<`，不会提前将边界本身饱和或清零。正负零均输出 1。
低端行为是用户指定的边界置零策略：例如 `exp(-88)` 的数学结果仍可表示成 FP32 次正规数，但 V2 按约定输出零。`1e-5` 相对误差只适用于保留原算法的区间；边界外按上述输出位编码检查。

关键用例：

| 输入位编码 | 输入含义 | V2 输出 |
|---|---|---|
| `c2aeac4f` | 下界内相邻值 | `00800026` |
| `c2aeac50` | 下界本身 | `007fffae` |
| `c2aeac51` | 比下界小一个 FP32 步长 | `00000000` |
| `42b17216` | 上界内相邻值 | `7f7ffee8` |
| `42b17217` | 上界本身 | `7f7fff67` |
| `42b17218` | 比上界大一个 FP32 步长 | `7f800000` |
| `43000000` / `c3000000` | +128 / -128 | `7f800000` / `00000000` |
| `7f7fffff` / `ff7fffff` | 最大 / 最小有限 FP32 | `7f800000` / `00000000` |

## 实现与 TIE 转译

第一级直接对原始输入 `x[30:0]` 做幅值位编码比较，并用 `x[31]` 区分方向。对负数，幅值越大，数值越小，因此低端条件为负号且幅值编码大于 `42aeac50`。此判断早于 Q24 截断，不会被大输入的移位截断影响。

原版所有乘加、查表、截位、舍入表达式保持一致。原输出先接到新增 `core_y`，最终选择优先级为 NaN、上界饱和、下界置零、`core_y`。NaN 优先级最高，避免其位编码被误判为普通越界值。

仍然是纯前向组合逻辑，没有 `if`、`always`、`signed`、`$signed`、反馈或时钟，保留七处 `// please add tie pipe here`。
实际插入 TIE 流水线时，必须将 `input_nan`、`saturate_high`、`saturate_low` 与该输入的计算结果一起通过前六个边界，最后在第七级选择输出；每一级注释均已标明。无需保存完整 x 到末级。
七级划分和 II=1 的设计意图保持不变；新增比较与选择逻辑的实际面积/时序尚需目标工具综合确认。

## 完整回归

```sh
bash run_v2.sh
```

只使用 Python 标准库和已有 Icarus Verilog。可通过 `PYTHON`、`IVERILOG`、`VVP` 指定工具。`scripts/verify_v2.py` 和 `tb/tb_exp_fp32_v2.sv` 完成：

1. 重新生成并验证原有 454,400 个输入，检查 V2 与原定点模型逐位一致。
2. 4,144 个定向输入：边界等值及两侧相邻值、所有 256 种指数的代表性尾数和正负符号、±0、次正规输入、±Inf、NaN、大数、重复值和连续切换类别的输入。
3. 固定种子 `20261001` 的 300,000 个完整 32 位随机编码输入，包含特殊值和远超 ±128 的有限输入。
4. **逐个穷举 `64 <= |x| <= 128` 的 16,777,218 个 FP32 输入**，同时驱动原版和 V2；通过独立的实数大小比较确定饱和/置零条件，区间内检查 `exp(x)` 相对误差。
5. 每个用例均比较 `v2.core_y` 与原模块 y，检查全部计算路径未变。另静态核对原有 wire 表达式、无反馈依赖关系、受限 RTL 语法和七个流水线标记。
6. 对边界及区间内最坏点使用 80 位 Decimal 参考复核。

合计 **17,535,762** 次 RTL 输入测试。覆盖范围外的输入采用定向及随机检查，没有声称枚举全部 `2^32` 编码。

### 实际验证结果（2026-10-01）

Icarus Verilog 12.0 编译无警告，全部测试通过。统计包含不同测试阶段重复施加的输入：

| 检查类别 | 通过次数 |
|---|---:|
| 区间内，逐位保持原输出且相对误差达标 | 6,911,557 |
| 高端饱和为 +Inf（含 +Inf 输入） | 5,220,324 |
| 低端置为 +0（含 -Inf 输入） | 5,402,646 |
| NaN 规范化 | 1,235 |
| 合计 | 17,535,762 |

区间内最大相对误差为 **6.674177856931406e-6**（80 位复核），出现在下界 `c2aeac50`。
每次输入的 `core_y` 均与原版逐位一致。原版 RTL SHA-256 与之前边界报告完全相同。
保存的验证记录见 [v2_validation.json](v2_validation.json)，其中包含新旧 RTL 哈希、全部计数及高精度参考值。

输出位于 `build/v2/`：

- `summary.json`：最终计数、RTL 哈希、误差、80 位精度复核值。
- `simulation.log`、`compile.log`：仿真进度及编译日志。
- `directed.csv`：定向用例的输入、V2 输出和期望值，位编码均为十六进制；不适用数学相对误差的饱和/置零/NaN 用例标记为 `-1`。
- `inputs.json`、`vectors.txt`、`base_vectors.txt`：实际验证输入及逐位参考值。

原 `run.sh`、原调试接口 `debug.sh` 和之前的边界报告仍针对 V1；验证 V2 请使用 `run_v2.sh`。本版本未改变这些入口的默认模块。
