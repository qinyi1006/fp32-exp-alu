# V3：负向下界扩展到 0xC2CE8ED0

新文件 [rtl/exp_fp32_v3.v](../rtl/exp_fp32_v3.v)，模块名 `exp_fp32_v3`，基于 V2 独立生成，不依赖 V2 实例。V1、V2 均保留。

## 行为与边界

| 输入条件 | V3 输出 |
|---|---|
| `x > 88.72283172607421875` (`0x42b17217`) | +Inf (`0x7f800000`)，正向上界与 V2 相同 |
| `x < -103.2789306640625` (`0xc2ce8ed0`) | +0 (`0x00000000`) |
| 等于新下界 | 最小正次正规数 `0x00000001` |
| 上下界之间 | 同一套 Q24 查表/二次多项式近似，按结果量级打包为正规或次正规 FP32 |
| +Inf / -Inf | +Inf / +0 |
| 任意 NaN | `0x7fc00000`，与 V2 一致 |

比较仍为严格 `>` / `<`。新下界的数学真值约为 `1.4012973984546623e-45`，而 FP32 最小次正规数 `2^-149` 约为 `1.4012984643248171e-45`。
新下界略小于 `ln(2^-149)`，该点正确舍入仍是 `0x00000001`。
比它更小一个 FP32 步长的 `0xc2ce8ed1` 按指定策略输出零，即使数学 exp 的正确 FP32 舍入仍可能非零。因此它是用户指定的清零阈值，不是 IEEE 最近舍入模式下的自然归零阈值。

## 为什么不能只替换比较常数

V2 的 `y_q24` 为 32 位，整数部分 `k` 为 8 位补码，只能表示 -128～127。
新下界处 `x*log2(e)` 略小于 -149，取 floor 后 `k=-150`；保持原位宽会回绕成正值。
另外，V2 直接拼接指数和 fraction，没有次正规数打包，旧下界附近只是误差暂时未超标。

V3 修改三处：

1. `saturate_low` 改用原始 FP32 幅值编码 `31'h42ce8ed0`。正向比较表达式保持原样。
2. `negative_y_q24` / `y_q24` 扩至 33 位，`k` 扩至 9 位，仍使用显式补码与无符号位向量，不引入 `signed` 或 `$signed`。乘法位宽、Q24 小数位、表和多项式系数都不变。
3. 新增次正规数缩放和最近偶数舍入；所有舍入直接从原始 25 位 `mant_q24` 完成一次，避免先舍入到 Q23 再移位的双重舍入。

## 次正规数打包公式

设 `M=mant_q24` 是存储的整数，算法近似值为：

```text
approx = M * 2^(k-24)
```

次正规数的单位为 `2^-149`，所以输出 fraction 所表示的整数应为：

```text
S = round_to_nearest_even(approx / 2^-149)
  = round_to_nearest_even(M * 2^(k+125))
```

这里的 **125 = 149 - 24**。对 `k=-127 ... -150`，对应右移 `s=-k-125`，范围为 2～25。
代码中 `biased_exp=k+127`，因此同一移位量也可写作 `s=2-biased_exp`。

`{M,25'b0}` 逻辑右移 s 后，上 25 位为整数商，下一位为 guard，剩余 24 位 OR 为 sticky。
仅在 `guard && (sticky || 商的最低位)` 时加一。这样也覆盖精确中点的偶数舍入。
若次正规数舍入进位到 `S=0x00800000`，直接将这个整数作为 FP32 位编码，就自然得到最小正规数。
对于正规数固定 `s=1`，这个舍入表达式与 V2 原表达式等价。

## 精度含义

原有 `[-64,64]` 的 `1e-5` 精度要求保持不变，正规结果区间也继续验证该要求。所有测试中的正向输入与 V2 逐位相同。
新增的深次正规区间不能统一承诺 `1e-5` 相对误差：接近最小值时，输出只能取 `1*2^-149`、`2*2^-149` 等离散值，正确舍入本身也可能带来接近 1/3 的相对误差。

因此测试分别检查：

- 舍入之前 Q24 算法近似的相对误差不超过 `1e-5`。
- 次正规数输出必须精确符合对该近似值的最近偶数舍入。
- 最终误差满足 `abs(output-exp(x)) <= exp(x)*1e-5 + 2^-150`；后一项是半个次正规数 ULP。
- 另报告最终数学相对误差、与数学 exp 正确舍入结果的 ULP 距离，不能将它们与“打包器舍入正确”混为一谈。

查表和多项式仍是近似算法，V3 不宣称每个结果都等于数学 exp 正确舍入后的 FP32。

定向 RTL 结果：

| 输入位编码 / 数值 | V2 输出 | V3 输出 |
|---|---|---|
| `0xc2ce8ecf`，新下界内相邻值 | `00000000` | `00000001` |
| `0xc2ce8ed0`，新下界本身 | `00000000` | `00000001` |
| `0xc2ce8ed1`，新下界外相邻值 | `00000000` | `00000000` |
| `0xc2aeac50`，旧下界本身 | `007fffae` | `007fffd7` |
| -88 | `00000000` | `0041edc4` |
| -89 | `00000000` | `001840fc` |
| -100 | `00000000` | `0000001b` |
| -103 | `00000000` | `00000001` |
| `0x42b17217`，正向上界 | `7f7fff67` | `7f7fff67` |
| `0x42b17218`，正向上界外相邻值 | `7f800000` | `7f800000` |

旧下界本身已经是次正规数，因此补全打包后该点的结果会改变；正规结果区域保持 V2 的行为。

## 流水线和成本

保持无 `if`、无 `always`、无有符号语法、无时钟和无反馈的组合实现。仅通过注释建议流水线位置，II=1。
为分开尾数加法与新增的可变移位/舍入，V3 使用 **8 个建议流水边界**：第 7 级完成 `mant_q24` 加法，第 8 级完成舍入、打包和饱和选择。
`k` 从第 2 级开始多保存一位；`input_nan`、`saturate_high`、`saturate_low` 必须伴随对应数据通过前 7 个边界。
新增成本主要是可变移位和 guard/sticky 逻辑，没有新增乘法器或查表项。实际面积、时钟频率需在目标 TIE 工具中综合确认。

## 验证和复现

```sh
bash run_v3.sh
```

使用 Python 标准库和已有 Icarus Verilog，无新增依赖。可通过 `PYTHON`、`IVERILOG`、`VVP` 指定工具。

- 原有 454,400 个输入向量重新生成、验证。
- 6,747 个定向输入覆盖新旧阈值、正向边界、所有 256 种指数、subnormal/normal 转换、k=-150～-125 附近以及次正规数舍入中点。
- 300,000 个完整 32 位随机编码，加上 100,000 个专门落在负向新增区间附近的随机输入。
- 对 `64 <= |x| <= 128` 的 16,777,218 个 FP32 输入直接做 RTL 穷举，正常/特殊值分类、正向兼容性、次正规舍入和误差分别检查。
- 200 个打包器内部定向用例，覆盖移位量 1～25、guard/sticky、中点取偶及进位成最小正规数。这些强制内部信号的白盒用例不计入真实输入总数。
- 对最终最坏点及关键阈值使用 80 位 Decimal 复核；静态核对无反馈、受限语法、8 个流水线标记和正向比较表达式不变。

真实输入合计 17,638,365 次；覆盖范围外采用定向及随机检查，没有枚举全部 `2^32` 编码。
结果位于 `build/v3/summary.json`，定向 RTL 输入/输出位编码位于 `build/v3/directed.csv`，编译及扫描日志位于同目录。
V1/V2 的运行、调试和验证入口继续保留原有模块，不会自动切换到 V3。

## 本次验证结果（2026-10-08）

17,638,365 次真实输入测试及 200 个打包器单元用例全部通过，Icarus 编译无警告。完整统计、RTL SHA-256 和关键点的高精度复核保存于 [v3_validation.json](v3_validation.json)。以下最大值针对上述测试集合。

| 指标 | 实测结果 | 最坏点输入 |
|---|---|---|
| 正规结果最大相对误差 | `1.9260756182e-6` | `0x3d314b3f` |
| FP32 打包前算法最大相对误差 | `1.8689959002e-6` | `0x3d314b3f` |
| 次正规结果最大相对误差 | `0.3333322024`，约 33.33% | `0xc2cdbf37` |
| 次正规结果最大绝对误差，以 `2^-149` 为单位 | `15.0132861566` | `0xc2aeac5a` |
| 次正规结果与数学 exp 正确舍入值的最大 ULP 距离 | 15 | 包括 `0xc2aeac50`、`0xc2aeac5a` |

对 `0xc2cdbf37`（约 -102.87346649），数学真值约为 `1.49999746 * 2^-149`，V3 和正确 FP32 舍入结果均为 `0x00000001`。该点的约 33.33% 相对误差来自 FP32 表示粒度，不能靠增加内部 Q 小数位消除。

2,189,522 次次正规区间输入检查中，有 272,116 次输出与数学 exp 正确舍入结果不同，但全部符合对原 Q24 算法近似值的最近偶数舍入及上述误差界。这些计数包含回归、随机和穷举中的重复输入。15 ULP 的最大距离出现在接近最小正规数处，相对误差仍约 `1.8e-6`；它来自原算法近似误差，不应归因于打包器或深次正规区间的量化。

全部被测正向输入逐位匹配 V2。新旧 RTL 的近似尾数逐位相同；V2 文件 SHA-256 与原验证报告一致。
